# 🎧 Manhwa Reader Sound System — Архітектура, Баги, Цілі та Статус

Цей документ фіксує поточний стан, архітектуру, історію багів, шляхи їх вирішення та подальші цілі звукового рушія читалки манхви.

---

## 1. Загальна концепція та ціль

Створити кінематографічний, повністю автоматичний звуковий супровід під час читання манхви (webtoon) та новел:
1. **ШІ-Адаптивність (Gemini 3.1 Flash-Lite + Files API):**
   - ШІ аналізує весь PDF глави за 1 раз.
   - Генерує звукову мапу (`sound_timeline.json`) у папці глави.
   - Розбиває сторінки на 4 чверті (`f: 0, 1, 2, 3`), прив'язуючи сцени до конкретних висот екрана.
2. **Динамічний рушій (SoundEngine):**
   - Відстежує скрол читача. Розраховує позицію за нижньою частиною екрана (75% висоти вікна — куди спрямований погляд користувача при читанні нових фреймів).
   - Плавний кросфейд (Player A <-> Player B) між фоновими мелодіями/ембієнтом при зміні локації або настрою сцени.
   - Запуск коротких SFX (удари, гарчання монстра, сміх, кроки тощо) саме в момент появи дії.
   - Захист від подвійного спрацьовування та пропуск звуків при різкому перемотуванні на кілька сторінок вперед.
   - Підтримка початку читання з будь-якого відсотка (наприклад, 45% чи 80%) — рушій миттєво підхоплює фоновий ембієнт поточної сцени без тиші.

## 2. Структура файлів і папок

```text
manhwa_reader/
├── sound_system/
│   ├── ai_sound_analyzer.py      # Модуль запитів до Google Gemini (Files API + Schema JSON)
│   ├── sound_engine.py           # Аудіорушій (Qt Multimedia: Player A, Player B, SFX Player)
│   └── sound_studio.py           # Вікно створення рецептів мікшування звуків
├── sounds/
│   ├── ambient/                  # Фонові локації (forest, cave, dungeon, city, tavern, rain тощо)
│   ├── sfx/                      # Короткі ефекти (sword_clash, heavy_strike, monster_roar, run тощо)
│   ├── ui/                       # Звуки інтерфейсу та довгі саундтреки (test_sound.wav, click.mp3 тощо)
│   ├── my_sounds/                # Папка користувача для власних OST треків
│   └── sound_recipes.json        # Рецепти багатошарового комбінування звуків
└── library/
    └── <Назва_Манхви>/
        └── chapter_XXX/
            ├── chapter_pdf_XXX.pdf
            └── sound_timeline.json   # Згенерована звукова мапа для глави
```

## 3. Історія критичних багів та їх виправлення

### 🔴 Баг 1: Виліт програми при початку скролу сторінки (CRITICAL)
- **Симптом:** При відкритті глави 5 навіть найменший рух скролу викликав негайне падіння/закриття програми без зрозумілих логів у консолі.
- **Причина:**
  1. В `reader.py` список `self.page_labels` зберігає кортежі `(ch_num, QLabel, cache_key)`. У циклі `on_scroll` код писав `for idx, lbl in enumerate(self.page_labels): lh = lbl.height()`, що викликало `AttributeError: 'tuple' object has no attribute 'height'`.
  2. В `sound_engine.py` в кінці методу `on_scroll_position` викликався сигнал `self.cue_triggered.emit(mood, sfx, page, fraction)`, де змінна `mood` була невизначена (`NameError: name 'mood' is not defined`), викликаючи миттєвий краш застосунку.
- **Виправлення:**
  - Розпаковано кортеж: `lbl = item[1] if isinstance(item, (tuple, list)) else item` та обгорнуто в безпечний `try...except`.
  - В `sound_engine.py` виправлено на `self.cue_triggered.emit(self.current_mood, sfx, page, fraction)`.

### 🔴 Баг 2: Зависання і виліт кнопки «Обрати папку»
- **Симптом:** Натискання кнопки вибору папки бібліотеки зависало або закривало програму.
- **Причина:** Виклик `QFileDialog` екземпляром з прапорцями в поєднанні з конфліктами нативних діалогів Windows викликав deadlock головного потоку Qt.
- **Виправлення:**
  - Переведено на статичний надійний метод `QFileDialog.getExistingDirectory(..., QFileDialog.Option.ShowDirsOnly | QFileDialog.Option.DontUseNativeDialog)`.
  - Поле введення шляху зроблено ручним і текстовим з подією `editingFinished` — можна просто копіювати та вставляти шлях.

### 🔴 Баг 3: Тестовий звук (test_sound) запускався з затримкою і не вимикався
- **Симптом:** Довгий старт тестової мелодії при перетягуванні повзунка, і звук продовжував грати після переходу з вкладки налаштувань.
- **Причина:**
  - Файл `test_sound.mp3` мав тривалість 33 секунди з тишею та плавною преамбулою на старті.
  - При перемиканні вкладок зупинявся лише старий `_test_audio_player`, а `sound_engine`, який грав `test_sound` через `play_ambient`, не скидався.
- **Виправлення:**
  - Згенеровано чистий, якісний `test_sound.wav` (гармонійний акорд 4 сек) з миттєвим стартом без жодної мілісекунди тиші.
  - У `_switch_tab` додано примусову перевірку: при переході з вкладки налаштувань (індекс 3) `test_sound` негайно вимикається (`stop_all(fade=False)`).

### 🔴 Баг 4: Початок читання з середини глави (наприклад, 45%)
- **Симптом:** Читач відкриває главу на 45% чи 80% — спочатку повна тиша, поки не натрапить на наступну зміну сцени.
- **Причина:** Раніше перевірявся лише перший трек на позиції `(0, 0)`.
- **Виправлення:**
  - У `sound_engine.py` реалізовано ретроспективний пошук: знаходить останній активний ембієнт сцени перед або на поточній позиції читача і вмикає його одразу.

### 🔴 Баг 5: Кількість сторінок у Главі 5 (39 vs 83)
- **З'ясовано:**
  - У бібліотеці є дві манхви:
    - *«Стал сторонником злодеев [RU]»* — глава 5 має рівно **40 сторінок** у PDF, для неї ШІ згенерував **39 елементів мапи** (покриває всю главу від початку до кінця!).
    - *«Revenge of the Iron-Blooded Sword Hound»* — глава 5 має **83 сторінки**, для неї згенеровано 25 ключових подій (битва в підземеллі, удари, гарчання монстра).

## 4. Як працює розрахунок фрейму на екрані (Фокус зору)

- Замість вимірювання за верхнім краєм екрана (`value`), розрахунок ведеться за точкою читання:
  $$\text{focus\_y} = \text{scroll\_value} + 0.75 \times \text{viewport\_height}$$
- Коли знизу на екран виїжджає новий кадр манхви (або сторінка), рушій заздалегідь підхоплює його номер та четвертину (`cur_frac = 0..3`).
- Це забезпечує ідеальний таймінг: звук меча чи крику звучить саме тоді, коли око читача доходить до відповідного фрейму.

## 5. Поточні та майбутні цілі (Roadmap)

1. **Preload SFX (Кешування звуків глави в пам'ять):**
   - При старті глави зчитувати всі SFX з `sound_timeline.json` і заздалегідь завантажувати їх аудіобуфери в пам'ять, щоб вони відтворювалися без жодної мікрозатримки звернення до диска.
2. **Візуальний індикатор у читалці:**
   - Маленька напівпрозора плашка або іконка (за бажанням користувача), яка показує поточний настрій/локацію сцени (наприклад: *🏰 Dungeon — Tense*).
3. **Автоматична перевірка відсутніх SFX:**
   - Якщо ШІ призначив звук, якого немає в папці `sounds/sfx`, автоматично обирати найближчий за синонімом або використовувати безпечний дефолт.
